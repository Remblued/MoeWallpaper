# 接入你自己的图源（自定义 API）

> 状态：`v0.2.0` 起。这是整个应用里**唯一需要你手写 JSON** 的功能，
> 所以这份文档按"你遇到问题时该翻哪一段"来组织。

内置的 5 个图源受限于那些接口给什么、以及它们的条款。自定义图源把"我能看什么"
从我们写死的 5 份清单，变成你自己的清单——任何**一次返回一批图片**的 HTTP 接口都能接。

## 0. 一分钟版本

1. 打开应用，点右上角的 🧩 →「打开文件夹」。
2. 把一份 `.json` 放进那个文件夹（或点「导入 .json…」，**导入前会先校验**）。
3. 回到应用点「重新加载」。图源出现在下拉框的「我的图源」那一组里。
4. 没出现？面板里的红字写着原因——**校验不过的配置不会生效，但也不会影响别的图源**。

想先有个能跑的东西：点「生成示例配置」，它会写出一份**真的能拉到图**的配置
（不是占位符），照着改最快。

## 1. 文件放在哪

```text
%APPDATA%\com.remblued.moewallpaper\sources\*.json
```

展开是 `C:\Users\<你>\AppData\Roaming\com.remblued.moewallpaper\sources\`。

**为什么是这里**，而不是安装目录或缓存目录：

- 安装目录可能没有写权限（Program Files），而且升级时会整个替换。
- 缓存目录（`%LOCALAPPDATA%\...`）是**随时可以清空**的东西。配置放进去，将来某次
  「清空缓存」就会把你的配置一起删掉。两种生命周期不同的数据不该共用一棵树。

规矩（都来自实现，不是约定）：

| 项 | 规则 |
| --- | --- |
| 扩展名 | 只读 `.json`（大小写不敏感）；`.json.txt`、`.txt` 一律不读 |
| 隐藏文件 | `.` 开头的跳过 |
| 编码 | **必须 UTF-8**。记事本存「UTF-8 with BOM」也行（BOM 会被忽略）；存「ANSI」= GBK，会明确报"不是 UTF-8 编码" |
| 大小 | 单个文件 ≤ 256 KB |
| 数量 | 单个文件 ≤ 50 个图源 |
| 顺序 | 内置图源永远在前面；你的文件按**文件名**排序，所以顺序是稳定的 |
| id | 全局唯一。和你自己别的文件、和内置图源撞了，后加载的那条被跳过并报错 |
| 导入的文件名 | 会清洗掉目录和非法字符（`../x.json` → `x.json`，`a b.json` → `a_b.json`）；**同名直接覆盖** |

> 一个文件坏了，不影响别的文件，也不影响程序启动。**这是有意的**：
> 手写 JSON 一定会写错，写错的时候最需要的是"哪个文件哪一条怎么改"。

## 2. 一份最小可用的配置

下面这份是真的、能跑的（nekos.best，一个只给安全内容的动漫图接口）：

```json
{
  "schemaVersion": 1,
  "sources": [
    {
      "id": "my-neko",
      "name": "我的 neko 源",
      "request": {
        "url": "https://nekos.best/api/v2/neko?amount={limit}",
        "headers": { "Accept": "application/json" }
      },
      "response": {
        "itemsPath": "results",
        "imageUrl": "url",
        "pageUrl": "source_url",
        "width": "dimensions.width",
        "height": "dimensions.height"
      },
      "filter": { "sfwSafeEndpoint": true }
    }
  ]
}
```

- 没有 `itemsPath`？说明响应本身就是数组（safebooru 的 `dapi` 就是这样）。
- `width`/`height` 不写，图源就"没有尺寸"，分辨率/比例筛选对它无效——但界面会
  如实说"这个图源不提供图片尺寸"，不会假装筛过了。
- 没有缩略图就别写 `thumbnailUrl`：网格会直接加载原图，一页 20 张大图很费流量。

## 3. 字段表

### 3.1 文件

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schemaVersion` | ✅ | 现在只能是 `1`。写 `2` 会提示"这是更新版本的程序写的，请升级" |
| `sources` | ✅ | 图源数组，最多 50 个 |

`_` 或 `$` 开头的键**当注释**：`"_comment": "随便写"`，程序不读、也不报警。
JSON 没有注释，这是唯一的写法。

### 3.2 图源

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `id` | ✅ | —— | 只能用 `a-z` `0-9` `.` `_` `-`，以字母或数字开头，≤64 字符，全局唯一。它是报错文案里的名字，所以不允许中文/大写 |
| `name` | ✅ | —— | 下拉框里显示的名字，≤48 字（超了会被截断） |
| `enabled` | | `true` | 写 `false` 就是"加载但不显示"。**v0.2.0 起默认 true**：忘了写不会导致"文件明明放进去了却看不到" |
| `homepage` | | —— | 图源主页，仅供显示/溯源 |
| `contentNote` | | —— | 内容提示，显示在名字旁边（内置的 lolicon 用它标「尺度较大」）。**是提示，不是过滤器** |
| `request` | ✅ | —— | 怎么问 |
| `response` | ✅ | —— | 怎么读答案 |
| `filter` | ✅* | —— | 附加过滤 + **内容安全声明**（见 §6） |
| `search` | | 无 = 不支持搜索 | 搜索端点。不写整块 = 界面上搜索框对这个图源禁用 |

### 3.3 `request`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `url` | ✅ | 地址模板，占位符见 §4。必须是 http(s) |
| `method` | | 只支持 `GET`，写别的会**报错拒收**（不是运行时才发现） |
| `headers` | | 键值对。需要 `Accept: application/json` 的接口就写在这里 |

### 3.4 `response`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `itemsPath` | | 图片数组在响应里的位置，点号路径（`data`、`data.list`）。省略 = 响应本身就是数组 |
| `imageUrl` | ✅ | 原图地址的字段路径 |
| `thumbnailUrl` | | 缩略图字段路径。网格用它，详情页用原图 |
| `pageUrl` | | 原网页地址（详情页的「打开原网页」） |
| `tags` | | **目前是死配置**：格式里有、没有代码消费它。写了不会报错，但也不会显示 |
| `width` | | 原图宽度字段。数字和数字字符串都认 |
| `height` | | 原图高度字段。和 `width` 必须成对（只写一个会警告） |
| `resolution` | | 合在一起的尺寸，形如 `"2560x1440"`（360 壁纸就是这样），代码会拆。和 `width`/`height` 同时存在时以后者为准 |

### 3.5 `filter`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `sfwQuery` | *二选一* | 追加到请求地址末尾的安全参数，**裸参数**（`purity=100`、`r18=0`），不要带 `?`/`&` |
| `sfwSafeEndpoint` | *二选一* | 声明"这个接口本身只提供安全内容"，用于没有分级参数可配的图源 |
| `httpsUpgrade` | | 把图片地址的 `http://` 换成 `https://`。接口只给 http、但图在 https 下可取时用 |
| `randomOffsetMax` | | 把 `{offset}` 换成随机起点。**第 1 页永远同一批**的偏移量分页接口必须配 |
| `randomPageIndexMax` | | 把 `{pageIndex}` 换成随机页码。同上，用于页码分页的接口 |

`random*` 为什么必须配：不配的话用户每次打开、每次切回这个图源看到的都是同一批图，
而且**关掉重开也一样**——界面上这和"缓存坏了"完全无法区分。同一类问题在 360 和
safebooru 上各踩过一次，详见 [SOURCES-CN §0.1](SOURCES-CN.md)。

### 3.6 `search`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `url` | ✅ | 搜索地址模板，**必须包含 `{query}`**（没有就报错拒收：关键词会被静默丢掉） |
| `english` | `false` | 关键词要不要先查内置的中英词表翻成英文（wallhaven、booru 类只吃英文） |
| `underscoreTags` | `false` | 把关键词里的空格换成下划线。**booru 类必须开**：`hatsune miku` 被当成两个标签（AND）→ 0 条 |
| `wildcardFallback` | `false` | 精确标签搜到 0 条时，补一个结尾 `*` 再试一次。只在接口认前缀匹配时开 |

## 4. 占位符

配置是静态 JSON，不能在 JSON 里做算术，所以这些替换由代码完成：

| 占位符 | 换成 | 用在哪 |
| --- | --- | --- |
| `{page}` | 页码，从 1 开始 | 页码分页的接口 |
| `{pageIndex}` | 页码 − 1（从 0 开始） | Gelbooru 系的 `pid` |
| `{offset}` | `(page - 1) * 每页数量` | 偏移量分页的接口（360 的 `start`） |
| `{limit}` | 每页数量（目前固定 20） | 大多数接口 |
| `{query}` | 百分号编码后的关键词 | **只在 `search.url` 里有效** |

两处容易踩：

- 占位符**打错一个字母就是错误**，不会静默放过：`{pages}` 会得到一条红字，因为
  `Url::parse` 会把它编码成一个"合法但服务端看不懂"的地址，请求 200、结果为空。
- `{query}` 写在 `request.url`（浏览地址）里是**错的**：浏览时它不会被替换。

## 5. 搜索

不配 `search` 整块 = 界面把搜索框禁用并写"该图源不支持搜索"。
**这是有意的**：配了但静默无效，比不配更糟——用户会以为程序坏了。

接搜索时最容易出错的不是代码，是**目标站对标签的定义**：

- booru 的标签是"全站用户约定"，带下划线、带括号：`lycoris` 不存在，
  `lycoris_recoil` 才是；`elaina` 不存在，`elaina_(majo_no_tabitabi)` 才是。
- 所以 `wildcardFallback` 值得开：精确搜到 0 条时补一个 `*` 做前缀匹配。
  代价是模糊——它会带出"名字以它开头"的别的东西，界面上会写明"这是前缀扩展的结果"。
- 搜 "0 条" 和 "搜不到" 在界面上必须能区分。我们的做法是：只在**放宽后拿到图**时给
  提示，放宽也空就照实说"没搜到"。

## 6. 内容安全是**硬要求**

`filter` 里 `sfwQuery` 和 `sfwSafeEndpoint` **必须有一个**，两个都没有的图源
**不会被加载**，面板里会有一行红字。

> 为什么这是错误而不是警告：从 `v0.2.0` 起配置是用户写的，没有 code review 了。
> 以前"图源忘了写安全参数"只有我们自己能发现，现在必须由代码在加载时问出这个问题。

两种正当情形：

1. **有分级参数就写参数**：`purity=100`、`r18=0`、`rating:general`。这是首选。
2. **没有参数可配**才写 `sfwSafeEndpoint: true`，它等于向以后的维护者承诺
   "这个接口不会返回越界内容"。内置 5 个图源各自的依据写在
   [SOURCES-CN §11](SOURCES-CN.md)。

反例：wallhaven 有 `purity`、lolicon 有 `r18`——**有参数就必须用参数**，
用一句声明代替等于撒谎。

## 7. 校验：哪些会拒收，哪些只是提醒

红字（`错误`）= **这条图源不加载**；黄字（`警告`）= 加载了，但多半不是你要的。

| 检查 | 级别 | 为什么 |
| --- | --- | --- |
| JSON 语法 / 编码 / 超过 256 KB | 错误 | 整份文件不生效 |
| `schemaVersion` 不是 1 | 错误 | 版本比程序新时要升级程序，不是猜 |
| 字段类型不对（`"enabled": "yes"`） | 错误 | 整份文件不生效 |
| `id` 不合规 / 重复 | 错误 | 它是选中值、报错文案的名字 |
| `request.url` 不是 http(s) / 不能解析 | 错误 | 请求根本发不出去 |
| 占位符不认识（`{pages}`） | 错误 | 会带着字面量发出去，结果为空 |
| `{query}` 出现在浏览地址里 | 错误 | 它永远不会被替换 |
| `method` 不是 GET | 错误 | 我们只实现 GET |
| 没有 `sfwQuery` 也没有 `sfwSafeEndpoint` | 错误 | 见 §6 |
| `search.url` 缺 `{query}` | 错误 | 关键词会被静默丢掉 |
| 不认识 / 拼错的字段 | 警告 | 这一项被忽略，并提示"是不是想写 `sfwQuery`？" |
| `request.url` 用 http | 警告 | 图片若也是 http，WebView 不加载，界面里全是裂图 |
| `width`/`height` 只配一个 | 警告 | 尺寸是成对的，少一个筛选对它无效 |
| `width`/`height` 和 `resolution` 同时配 | 警告 | `resolution` 不生效 |
| `random*Max` > 20000 | 警告 | 有的接口把这当滥用（safebooru 实测 15000 起拒绝），偶发报错最难查 |
| `sfwQuery` 带 `?`/`&` | 警告 | 会拼出两个 `?` |
| `name` 超过 48 字 | 警告 | 下拉框会截断 |

**一个文件里坏一条，不影响同文件里的其他条**；坏的那个文件也不影响其他文件。

## 8. 症状对照

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| 文件放进去了，下拉框里没有 | 校验没过（看面板红字）/ 写了 `enabled: false` / id 撞了内置图源 | 看面板；换个 id |
| 图源出现了，但没有一张图 | 服务端返回空数组、或翻到了很深的页 | 先看是不是"第 1 页永远同一批"（配 `random*`）；再确认接口自己能返回数据 |
| 缩略图全是裂的 | 图片地址是 http（WebView 不加载） | 加 `httpsUpgrade`，或换 https 图源 |
| 每张图都要等很久 | 没配 `thumbnailUrl`，网格在直接拉原图 | 找到接口的缩略图字段填上去 |
| 搜什么都 0 条 | 标签形态不对（空格 vs 下划线、中文 vs 英文标签） | 开 `english` / `underscoreTags`，或开 `wildcardFallback` |
| 每次打开都是同一批图 | 接口的第 1 页是确定性的 | 配 `randomOffsetMax` 或 `randomPageIndexMax` |
| 面板有黄字，能用吗 | 能。警告只是提醒某个设置可能不是你想要的 | 看黄字说的是不是事实 |
| 面板有红字，图源没了 | 那条图源被拒了，**什么都没加载** | 按红字改，改完点「重新加载」 |

## 9. 接一个新接口之前，先回答这八个问题

不是"能返回图片"就能接。完整的验收清单在
[SOURCES-CN §0.1](SOURCES-CN.md)，每条都来自一次真实事故。最少先回答这三条：

1. 这批图每次都是新的吗？（不是 → 配 `random*`）
2. 搜一个**保证不存在**的词，返回 0 条还是返回一堆图？（返回一堆 = 它只是相关性排序，
   这种源的正确做法是**不提供搜索**）
3. 图片地址在你的机器上能直接打开吗？（注意 http/https 和防盗链 Referer）

## 10. 隐私与边界

- 配置是**你本地的一个文本文件**，我们不读、不上传、也没有账户体系。
- `headers` 里如果放了 API Key，它是**明文**存放在你的用户目录里。别把带 Key 的配置
  提交到 GitHub（本仓库的 PR 只收图源格式的改进，不收带凭据的配置）。
- 请求从你的机器直接发出（或走你的系统代理），不经过我们的服务器。
- 第三方接口随时可能改或关。**图源是数据**——它挂了，改一段 JSON 就行，不用等我们发版。
- 我们不托管任何图片：只用接口给的地址，缓存缩略图和当前壁纸。
